2. ATURAN KERJA YANG TIDAK BOLEH DILANGGAR
======================================================================

2.1 Audit-first
---------------
Sebelum perubahan:
1. Baca source aktual.
2. Cari semua pemanggilan method/class terkait.
3. Baca test yang sudah ada.
4. Jalankan baseline targeted.
5. Jangan menebak nama file, constructor, schema, atau provider.

2.2 Batch dipercepat
--------------------
Pengguna meminta progres tidak lagi terlalu satu-per-satu.

Metode baru:
- Gabungkan 3 sampai 5 checkpoint yang masih satu domain.
- Contoh satu batch:
  repository + ViewModel + UI + wiring + test.
- Tetap berhenti bila muncul error pertama.
- Jangan memperbaiki error kedua sebelum error pertama selesai.

2.3 Urutan test wajib
---------------------
Untuk setiap batch:
1. dart format pada file yang berubah.
2. targeted test paling dekat.
3. test file terkait.
4. regression subsistem.
5. migration test jika schema berubah.
6. flutter analyze.
7. full flutter test.
8. device test.
9. negative path nyata.

2.4 Debug error pertama
-----------------------
Jika test gagal:
- ambil test pertama yang gagal;
- baca stack trace pertama;
- perbaiki akar masalah terkecil;
- jangan merombak beberapa file tanpa bukti;
- jalankan ulang targeted test tersebut;
- setelah hijau, lanjutkan urutan regression.

Contoh nyata yang sudah terjadi:
- matcher `find.textContaining()` menemukan dua pesan karena error tampil di
  banner halaman dan dialog;
- solusinya bukan mengubah repository, tetapi mempersempit finder ke descendant
  dari widget error dialog.

2.5 Database
------------
- Gunakan SATU AppDatabase bersama.
- Jangan membuat database auth kedua.
- Jangan menghapus migration lama.
- Jangan mengedit *.g.dart secara manual.
- Jangan mengedit generated schema secara manual.
- Gunakan Drift migration snapshots dan migration matrix.
- Setiap schema baru harus memiliki data-integrity test.

2.6 Keamanan lisensi
--------------------
JANGAN PERNAH:
- meminta private signing key;
- menampilkan private key;
- memasukkan private key ke kasir_offline;
- mengirim private key lewat chat, log, screenshot, atau repository;
- membuat ulang keypair tanpa prosedur recovery;
- menghapus backup private key;
- menampilkan token lisensi lengkap di history/log;
- mengklaim sistem mustahil dibajak.

kasir_offline hanya membawa PUBLIC KEY.
kasir_license_manager adalah satu-satunya aplikasi yang boleh mengakses private
key melalui secure storage.

2.7 PIN
-------
- PIN asli tidak boleh disimpan.
- Hash produksi: PBKDF2-HMAC-SHA256.
- Iterasi produksi: 120.000.
- Salt acak 16 byte.
- Test widget/repository yang tidak sedang menguji crypto boleh memakai
  `_FastPinHashService`.
- Jangan log PIN, hash, atau salt.

31. GO / NO-GO
======================================================================

GO hanya jika:
- tidak ada known data-loss blocker;
- migration old -> final teruji;
- license survives supported upgrade;
- role guard ada di business layer;
- private key backup teruji;

- release masih memakai debug signing;
- secret ditemukan di repo/log/artifact.
